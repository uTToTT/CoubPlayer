# CoubPlayer Downloader

Расширение для Chrome, которое добавляет на coub.com кнопку «скачать в CoubPlayer»
и умеет догружать ленту лайков и закладок.

## Зачем оно нужно

Скачать отдельный куб локальный сервер умеет и сам — публичный API отдаёт
ссылки на файлы без авторизации. Не хватает ему только **списка**: «что этот
пользователь лайкнул». Такой список отдаёт приватный timeline API, и только
залогиненному пользователю.

Раньше это решалось тем, что пользователь вручную доставал `remember_token`
из cookie и вставлял в настройки. **Этой куки больше нет вообще**: coub.com
перешёл на Supabase GoTrue, и сессия теперь лежит в `sb-gotrue-auth-token`.
Кука `HttpOnly`, то есть из консоли сайта её не прочитать, а `chrome.cookies`
её видит — на этом расширение и стоит.

Разделение ответственности такое:

| Кто | За что отвечает |
| --- | --- |
| расширение | авторизация, обход ленты, сбор permalink'ов |
| сервер | скачивание файлов, дедупликация, раскладка по плейлистам |

Поэтому расширение не проверяет перед отправкой, скачан ли ролик: он может
лежать на диске, но не в том плейлисте, который выбрали в меню. Сервер сам
не перекачивает то, что уже есть, и просто добавляет запись.

Расширение не качает файлы само: MV3 усыпляет service worker примерно через
30 секунд простоя, и долгая выкачка развалилась бы на середине. Сервер это уже
умеет, включая бэкофф при 403.

## Установка

1. Запустите CoubPlayer (он должен слушать `http://localhost:5000`).
2. Откройте `chrome://extensions`, включите **Режим разработчика**.
3. **Загрузить распакованное расширение** → выберите папку `extension`.
4. Войдите на coub.com под своей учётной записью.

Порт можно поменять в попапе расширения, если сервер поднят на другом.

## Как пользоваться

- **Один куб** — на странице `coub.com/view/…` появляется кнопка в правом
  нижнем углу; на карточках ленты — в правом верхнем углу по наведению.
  По клику выпадает список плейлистов — разложенный по группам и в том же
  порядке, что в плеере. Точкой отмечен тот, куда клали в прошлый раз,
  приглушены те, где этот ролик уже лежит. Выбор запоминается.

  От восьми плейлистов сверху появляется поиск: он сразу в фокусе, Enter
  забирает первый совпавший. Пока ищут, группировка убирается — на экране
  и так только совпавшее. Клавиши из поля до coub.com не доходят, иначе
  пробел ставил бы ролик на паузу прямо во время набора.

  Внизу меню — «Новый плейлист»: строка разворачивается в поле ввода
  (`prompt()` на чужой странице неуместен — он блокирует всё окно). Если в
  поиске набрано то, чего нет, строка предлагает завести плейлист сразу с
  этим именем, и тот же Enter это делает. После создания ролик кладётся
  в новый плейлист без второго клика.
- **Лента целиком** — иконка расширения → «Лайки» или «Закладки».
  - *только новое* — обход обрывается на первой странице, где всё уже скачано.
    Обычный режим для регулярной догрузки.
  - *всю ленту* — полный обход. Нужен, если в библиотеке есть пропуски.

Ролики кладутся в плейлисты `liked` и `bookmarks` — те же, что использовала
старая синхронизация. Плейлист создаётся автоматически.

Во время скачивания показывается оставшееся время и кнопка **Стоп**. Оценка
считается по фактической скорости с начала загрузки и между пачками только
убывает: пересчитывать её каждую секунду нельзя — счётчик обработанных стоит
на месте, а время идёт, и цифра росла бы на глазах. Пока лента собирается,
времени не показываем — сколько в ней страниц, заранее неизвестно.

«Стоп» обрывает обход ленты на ближайшей странице, а ожидание ответа сервера
— сразу. Пачку, которая уже у него в работе, он докачает: это не потеря, всё
скачанное попадает в плейлист независимо от того, дождались мы ответа или нет.

## Диагностика

Кнопка «Диагностика» в попапе показывает две вещи.

**Куки coub.com** с флагами `HttpOnly` / `Secure` / `SameSite`. Зелёным
подсвечены те, по которым сайт узнаёт пользователя. Пусто — вы не залогинены.

**Разведка** («Проверить доступ к ленте») дёргает обе ленты и проверку сессии
каждым способом и показывает код ответа.

**Запросы страницы** («Показать запросы») — то, что coub.com вызывает сам.
Кнопка «Скопировать» кладёт записи в буфер обмена целиком. Значения токенов
в записи не попадают — только схема авторизации и её длина.

## Какой API используется

Старый `/api/v2/` мёртв: ленты отвечают `403`, `users/me` — `404`. Нынешний
сайт ходит в два места, и нужное нам — во втором:

- **tRPC** — `https://coub.com/api/trpc/<процедура>?batch=1&input=<json>`.
  Процедуры батчатся пачками в одном URL (`social.viewerState`,
  `social.communityFollowState`, `notifications.summary`). Ролики там
  адресуются UUID, а не пермалинком. Для загрузки не нужен.
- **REST** — `https://coub.com/api/coub-site/…`. Здесь пермалинки живы.

### Лента

```
GET https://coub.com/api/coub-site/timeline?kind=hot&scope=<scope>&locale=ru&cursor=<курсор>
```

Отвечает `{ "items": [ { "permalink": "...", "title": "...", … } ], "next": "<курсор>" }`.
Листается курсором из `next`, а не номерами страниц; конец ленты — `next`
отсутствует. Страница отдаёт 5–10 роликов, размер не настраивается
(`limit`, `per_page`, `perPage`, `count` — все игнорируются).

Авторизация — **только куки**, никакого `Authorization`. Сессия живёт в
`sb-gotrue-auth-token` (Supabase GoTrue), но лента её оттуда не спрашивает.

Значения `scope`: `likes` и `bookmarks`. **Осторожно:** неизвестный `scope`
API молча игнорирует и отдаёт общую ленту «горячего» — опечатка здесь
означала бы не ошибку, а тихую закачку чужих роликов. Оба значения проверены:
аноним получает по ним пустой список, а не подмену.

### Проверка сессии

```
GET https://coub.com/api/realtime/token
```

`200` залогиненному, `401` анониму. Нужен потому, что пустая лента и
отсутствие сессии выглядят одинаково: и то и другое приходит как `200`
с `items: []`.

## Два пути к API

Лента ходит на одних куках, поэтому вопрос один: прикрепит ли Chrome куку к
запросу из service worker'а. Это зависит от его версии и от `SameSite` самой
куки, так что в [`coub-api.js`](src/coub-api.js) заложены два пути:

| Способ | Что делает | Когда сработает |
| --- | --- | --- |
| `direct` | `fetch` с куками из service worker'а | если Chrome сочтёт расширение первой стороной |
| `tab` | тот же запрос руками content script'а на вкладке coub.com | там запрос заведомо first-party, куки уходят всегда |

Расширение пробует их по очереди, при `401`/`403` берёт следующий и запоминает,
какой сработал. Для `tab` нужна открытая вкладка coub.com.

Есть и третий, `bearer` — `access_token` из куки Supabase в заголовке
`Authorization`. Ленте он не нужен и в обычной работе не используется, но
остался в разведке: если какая-то часть API однажды попросит токен, это
станет видно сразу. Формат куки Supabase гуляет от версии к версии — то голый
JSON, то он же с префиксом `base64-`, то массив, то нарезка на
`sb-…-auth-token.0`, `.1`; `readSupabaseToken()` разбирает все эти варианты.

## Состав

```
manifest.json        MV3, права: cookies + storage, хосты coub.com и localhost
src/background.js    service worker: маршрутизация сообщений, сценарий догрузки
src/coub-api.js      timeline API, обход страниц, диагностика кук
src/local-api.js     общение с CoubPlayer
src/content.js       кнопки на страницах + запасной канал к API + мост к рекордеру
src/page-probe.js    MAIN world: пишет, что страница вызывает своим fetch/XHR
src/popup.*          статус сервера, запуск догрузки, прогресс, диагностика
```

## Что ещё не сделано

- **Общий секрет для локального API.** Сейчас сервер пускает любой origin вида
  `chrome-extension://…` (см. `ExtensionCorsPolicy` в `Program.cs`). Обычная
  веб-страница такой origin подделать не может, так что дыры нет, но и другое
  расширение на этой машине формально не отсечено.
- **Отметки на самом coub.com** — подсветка превью тех роликов, что уже в
  библиотеке.
- **Прогресс от сервера.** Сейчас `/download` отвечает одним блобом в конце,
  поэтому расширение режет очередь на пачки по 5 ссылок: от размера пачки
  зависит и частота обновления прогресса, и то, насколько быстро срабатывает
  «Стоп». Правильнее — SSE или job-id с опросом: тогда прогресс шёл бы
  по каждому ролику, а остановка была бы мгновенной.
- **Firefox.** Нужен `browser.*` вместо `chrome.*` и свой формат MV3.
- **Селекторы карточек ленты** в `content.js` подобраны по текущей разметке
  coub.com и переживут не всякий редизайн. Плавающая кнопка на странице куба
  от разметки не зависит и должна работать всегда, а кнопки на карточках
  выключаются флажком в попапе.

  Разметка там БЭМ-овская, и широкий селектор вроде `[class*='coub__']`
  совпадает с каждым вложенным блоком карточки: кнопки садятся на все и
  выстраиваются лесенкой по диагонали. Отсюда два правила, которые лучше не
  ослаблять: селектор только по явным признакам карточки, и пропуск всего,
  что лежит внутри уже помеченной карточки.
